# 28 When2Call：什麼時候（不）該呼叫工具

Hayley Ross, Ameya Sunil Mahabaleshwarkar & Yoshi Suhara（哈佛大學、NVIDIA）· NAACL 2025 · [ACL Anthology](https://aclanthology.org/2025.naacl-long.174) · 本機檔案 `28_When2Call_NAACL2025.pdf` · 資料：[GitHub](https://github.com/NVIDIA/When2Call)

> 這篇和 27、29 是「pilot 題目與工具設計」補充進來的文獻，不在原本 26 篇的調查範圍內。

## 一句話重點

一般的 tool-calling 評測只看「有沒有呼叫對的工具」。這篇看的是**該不該呼叫**：資訊不夠時應該追問、沒有合適的工具時應該說做不到。結果發現各模型的預設反應差很多：**Llama 幾乎總是直接呼叫工具（用編造的參數），Qwen 則有六成會先追問**。

## 它在問什麼

模型拿到一組工具和一個使用者問題時，有四種可能的反應：

| 反應 | 什麼時候是對的 |
| --- | --- |
| (a) 直接用文字回答 | 本資料集刻意設計成永遠是錯的（題目都需要工具才能回答） |
| (b) 呼叫工具 | 工具對、資訊也夠 |
| (c) **追問使用者** | **工具對，但缺一個必填參數** |
| (d) 說做不到 | 沒有合適的工具 |

## 怎麼做

- 從 BFCL（最常用的 tool-calling 評測）挑出需要工具的問題，用 Mixtral 8x22B 改寫成三種版本：原題（該呼叫工具）、**刪掉一個必填參數的版本（該追問）**、相關但工具答不了的版本（該說做不到）。
- 測試集共 3,652 題，其中「該追問」1,062 題。
- 主要用選擇題評分（比較四個選項的機率），閉源模型則讓它自由回答，再用 GPT-4-Turbo 判斷屬於哪一類。

## 發現了什麼

**最重要的是附錄的混淆矩陣：遇到「該追問」的題目時，模型實際怎麼做？**

| 模型 | 正確追問 | 直接呼叫工具（編造參數） |
| --- | --- | --- |
| Llama 3.1 70B | 44 / 1,062（約 4%） | 1,009（約 95%） |
| Qwen 2.5 7B | 634 / 1,062（約 60%） | 410（約 39%） |
| Qwen 2.5 72B | 684 / 1,062（約 64%） | 365（約 34%） |

- **Llama 系列傾向一律呼叫工具**；Qwen 和 xLAM 比較會追問，但**幾乎不願意說「做不到」**。
- **模型越大不一定越好**：Qwen 2.5 的 3B、7B、72B 分數差不多。
- 閉源模型（GPT-4o、GPT-4-Turbo）較好，但仍有很大的進步空間。
- 用 When2Call 的資料再訓練可以改善，但容易讓模型變得太保守、該呼叫工具時也不呼叫。

## 跟我們的關係

**它直接回答了教授的疑問：模型「本來會不會問」，答案依模型而定，而且差距非常大。** 同樣缺一個必要資訊，Llama 約 4% 會追問、Qwen 約 60%。所以：

- 我們一定要分模型量 L0，不能用一個模型的結果推論全部；
- 如果用 Llama，低求助方向幾乎沒有空間（本來就不問），要照教授說的往「會問」的方向調；用 Qwen 則兩個方向都有空間。這也呼應精讀 03、21 的「模型效應大於語言效應」。

**一個重要的設計差異：在我們的實驗裡，「問老師」本身也是一個工具（`ask_teacher`）。** When2Call 的追問是用文字回答，而 Llama 這類「很愛呼叫工具」的模型，遇到「問老師」這個工具時，可能反而很樂意呼叫。也就是說，**「求助」做成工具還是做成文字，可能會大幅改變 L0**。pilot 可以兩種都試：

- 版本 A：`ask_teacher` 是一個工具；
- 版本 B：沒有求助工具，只能在回覆中用文字提問（對照 When2Call 的設定）。

**可以借用的地方：**

- **四分類的行為編碼**：我們的 `submit_answer`（直接作答）、`ask_teacher`（追問）、`skip`（放棄）幾乎一一對應它的 (b)(c)(d)，可以借用它的混淆矩陣報告方式。
- **自由回答 + LLM 評審**：如果有模型不支援原生 tool calling，可以讓它自由回答，再分類成四種行為。
- **「缺一個必填參數」的做法**：和我們條件不足題的設計原理相同。

**要區隔的地方：** 情境是一般的 API 呼叫（天氣、資料庫），不是學習情境；只有英文；沒有 persona，看的是模型的預設行為。
